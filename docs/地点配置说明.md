# 地点配置说明

`config/birdreport_locations.json` 是项目中所有观鸟地点的统一配置入口。本文档说明它的结构、在各脚本中的用途，以及后续添加地点的规则。

---

## 一、配置文件结构

```json
{
  "locations": [
    {
      "id": "shanghai_shiji_gongyuan",
      "name": "世纪公园",
      "province": "上海市",
      "city": "",
      "district": "",
      "mode": 0,
      "outside_type": 0,
      "default_days": 7,
      "point_aliases": [
        "世纪公园"
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一英文标识，供命令行 `--location` 参数使用 |
| `name` | string | **地点中文名，直接用于构建 `location_birds` 目录路径，必须与已有目录名完全一致** |
| `province` | string | 省份（直辖市直接填 `上海市`、`北京市` 等） |
| `city` | string | 城市（直辖市留空 `""`；地级市填完整名如 `深圳市`） |
| `district` | string | 区县（通常留空，`query_level: district` 时使用） |
| `mode` | int | birdreport API 参数，通常为 `0` |
| `outside_type` | int | birdreport API 参数，通常为 `0` |
| `default_days` | int | 默认回溯天数，公园类填 `7`，市级/省级区域填 `30` |
| `point_aliases` | array | 在中国观鸟记录中心可能出现的**所有地点名变体**，脚本逐一查询后自动去重合并 |
| `query_level` | string | 查询级别（可选，默认 `"point"`），见下节 |
| `districts` | array | 当 `query_level: "district"` 且需查询多个区县时使用 |
| `note` | string | 备注字段（可选），用于保存榜单标记等人工元数据，不参与抓取逻辑 |

---

## 二、query_level 查询级别

`query_level` 指定数据查询的地理范围，共四个级别：

| 值 | 含义 | 配套字段 |
|---|---|---|
| `"point"`（默认） | 按具体地点名查询 | 使用 `point_aliases` 列表 |
| `"district"` | 查询整个区县 | `district` 或 `districts` 数组 |
| `"city"` | 查询整个城市 | `city` 字段 |
| `"province"` | 查询整个省份 | `province` 字段 |

不同级别会自动清空不需要的字段：

| 查询级别 | pointname | district | city | province |
|---------|-----------|----------|------|----------|
| point   | ✓ 使用    | ✓ 使用   | ✓ 使用 | ✓ 使用    |
| district| ✗ 清空    | ✓ 使用   | ✓ 使用 | ✓ 使用    |
| city    | ✗ 清空    | ✗ 清空   | ✓ 使用 | ✓ 使用    |
| province| ✗ 清空    | ✗ 清空   | ✗ 清空 | ✓ 使用    |

### 各级别配置示例

**point（地点级，默认）**
```json
{
  "id": "beijing_aosen_north",
  "name": "奥森公园",
  "province": "北京市",
  "city": "",
  "district": "",
  "default_days": 7,
  "query_level": "point",
  "point_aliases": ["奥森北园", "奥森", "奥森南园", "奥林匹克森林公园北园"]
}
```

**district（区县级）- 单个区县**
```json
{
  "id": "beijing_haidian_qu",
  "name": "海淀区",
  "province": "北京市",
  "city": "北京市",
  "district": "海淀区",
  "default_days": 7,
  "query_level": "district",
  "point_aliases": []
}
```

**district（区县级）- 多个区县**
```json
{
  "id": "guilin_hexin_chengqu",
  "name": "桂林核心城区",
  "province": "广西壮族自治区",
  "city": "桂林市",
  "default_days": 7,
  "query_level": "district",
  "districts": ["象山区", "七星区", "阳朔县"],
  "point_aliases": []
}
```

多区县模式会依次查询每个区县后自动合并去重：
```
🔐 桂林核心城区 - 多区县查询: 3 个区县
  🔍 象山区: 调用 API ... ✅ 返回 17 条记录
  🔍 七星区: 调用 API ... ✅ 返回 11 条记录
  🔍 阳朔县: 调用 API ... ✅ 返回 3 条记录
📊 桂林核心城区 去重鸟种: 28
```

**city（城市级）**
```json
{
  "id": "guilin_shi",
  "name": "桂林市",
  "province": "广西壮族自治区",
  "city": "桂林市",
  "default_days": 7,
  "query_level": "city",
  "point_aliases": []
}
```

**province（省级）**
```json
{
  "id": "guangxi",
  "name": "广西壮族自治区",
  "province": "广西壮族自治区",
  "default_days": 30,
  "query_level": "province",
  "point_aliases": []
}
```

## 三、配置被哪些脚本使用

### `tools/run_weekly_refresh.py` — 周刷新主脚本

遍历配置中的每个地点，完成完整的数据刷新管线：抓取鸟种列表 → 下载缺失图片并上传至 Cloudinary → 复制最新 JSON 到前端目录。

```bash
# 刷新所有地点（最近 7 天）
python3 tools/run_weekly_refresh.py --days 7 --min-species 10

# 只刷新部分地点（使用 id 或中文 name 均可）
python3 tools/run_weekly_refresh.py --days 7 --locations shanghai_shiji_gongyuan 奥森公园
```

**路径构建逻辑：**
```
feather-flash-quiz/location_birds/<城市>/<name>/<日期>/
```
其中「城市」由 `location_utils.py` 从 `city` / `province` 字段推导（见下节）。

### `tools/location_utils.py` — 城市路径推导

| 情况 | `province` | `city` | 推导出的城市目录 |
|---|---|---|---|
| 直辖市（北京、上海、天津、重庆） | `北京市` / `上海市` / … | `""` | `北京` / `上海` / … |
| 地级市 | `广东省` | `深圳市` | `深圳市` |
| 省会或其他城市 | `陕西省` | `西安市` | `西安市` |

`point_aliases` 中的所有别名也会注册到映射表，因此**别名也可以正确解析到城市**。

### `tools/fetch_from_birdreport.py` — 单次抓取

```bash
python3 tools/fetch_from_birdreport.py \
  --location-config config/birdreport_locations.json \
  --location guilin_hexin_chengqu \
  --days 7
```

## 四、location_birds 目录结构

```
feather-flash-quiz/location_birds/
└── <城市>/          ← 由 city 或 province 推导
    └── <name>/      ← 完全等于配置中的 name 字段
        └── <日期>/  ← 格式 YYMMDD，如 260302
            ├── eurasian_tree_sparrow_cloudinary_urls.json
            └── ...
```

**重要：`name` 字段与目录名必须完全一致**，否则刷新时会创建新目录而不覆盖旧数据。

## 五、添加新地点的规则

在 `config/birdreport_locations.json` 的 `locations` 数组中追加一个对象：

### `id` 命名

- 全部小写英文 + 下划线，无空格
- 必须使用"城市前缀 + 语义 id"格式，避免跨城市冲突
  - ✅ `beijing_tiantan`、`shanghai_zhongshan_gongyuan`
  - ❌ `tiantan`（无前缀）

> **兼容性说明**：2026-03-10 起，配置已统一为城市前缀 id。旧 id（如 `aosen_north`）不再兼容命令行 `--location` 参数，可改用中文 `name` 参数代替。

### `name` 命名

- **优先检查 `location_birds` 目录下是否已有同名目录**，有则必须完全一致
- 若是新地点，填写在中国观鸟记录中心最常见的标准名称

### `point_aliases` 填写

列出该地点在中国观鸟记录中心**可能使用的所有名称变体**，常见情况：
- 全名 + 简称（如「上海滨江森林公园」和「滨江森林公园」）
- 园区子地点（如「世博文化公园双子山」并入「世博文化公园」条目）

`query_level` 为 `city` / `province` 的地点，`point_aliases` 可留空数组 `[]`。

### `default_days`

- 公园、具体地点：`7`
- 市级、省级区域：`30`

### 完整示例

```json
{
  "id": "shanghai_jinhai_shidi_gongyuan",
  "name": "金海湿地公园",
  "province": "上海市",
  "city": "",
  "district": "",
  "mode": 0,
  "outside_type": 0,
  "default_days": 7,
  "point_aliases": ["金海湿地公园", "金海湿地"]
}
```

## 七、常见注意事项

1. **`name` 与目录名不一致会导致数据分裂**：刷新时产生新目录而不覆盖旧数据，前端会同时展示两个版本。发现后需手动合并或重命名。

2. **新增地点先验证别名**：在中国观鸟记录中心搜索确认该地点的实际用名，再填 `point_aliases`，避免查询无结果。

3. **直辖市 `city` 留空**：北京、上海等直辖市 `city` 字段填 `""`，否则城市目录会变成 `上海市/上海市/...` 的双层结构。

4. **多区县控制数量**：`districts` 数组建议不超过 10 个；时间范围用 `default_days` 或 `--days` 控制，避免数据量过大。

5. **查询失败处理**：多区县模式下，若某个区县查询失败，系统会显示警告并继续查询其余区县；只要有一个区县成功，整体查询就成功。

6. **排序建议**：按省市归组，同城市的地点放在一起，便于维护。
